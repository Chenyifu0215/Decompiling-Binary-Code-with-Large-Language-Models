新增功能使用说明
================

本文档总结除 decompile_binary.py / decompile_helper.py（已有各自 usage）之外，
新增脚本与能力的使用方法。覆盖：静态修复闭环、LLM 签名修复、LLM 类型修复、
GUI、单元测试。

=====================================================================
一、总览：新增脚本清单
=====================================================================

  orchestrator.py      静态编译修复闭环（编译→失败→补丁→重试，收敛判据=编译成功）
  fix_signatures_llm.py LLM 签名修复（证据包→LLM 推断签名→回灌 Ghidra）
  fix_types_llm.py      LLM 类型/结构体错误修复（生成补丁修 .c 文件）
  fix_signatures.py     签名修复基础版（按 sigs.json 手工指定签名回灌）
  llm.py                LLM proposer 模块（fallback 规则库 + DeepSeek 调用）
  patch.py              补丁引擎模块（replace/regex，可重放）
  decompile_gui.py      桌面 GUI（拖拽反编译 + 签名修复 + 生成工程 + 静态修复）
  test_core.py          单元测试（pytest，测纯函数）
  启动反编译器.bat       双击启动 GUI

=====================================================================
二、环境变量（LLM 相关）
=====================================================================

  LLM_API_KEY    （必需）DeepSeek / OpenAI 兼容 API 的 key
  LLM_BASE_URL   （可选）默认 https://api.deepseek.com/v1
  LLM_MODEL      （可选）默认 deepseek-chat（快）；慢模型可用 deepseek-v4-pro

  仅用 --proposer fallback 时不需 key。

=====================================================================
三、各脚本用法
=====================================================================

■ orchestrator.py —— 静态编译修复闭环
    python orchestrator.py <binary> <decomp_dir> [options]

  关键参数：
    -o/--build-dir      输出 build 目录（默认 static_build）
    --proposer          fallback（默认，规则库）| llm（需 key）
    --map               GNU ld map 文件（过滤静态链接 libc，强烈建议）
    --max-iter          最大迭代轮数（默认 10）
    --no-prepare        跳过 decompile_helper，直接用现有 build 目录
    --make-cmd          覆盖 make 命令（需自带 -C <dir>）

  示例：
    python orchestrator.py test_complex.o test_out_fixed -o static_build
    python orchestrator.py busybox decomp_dir -o build --map busybox.map --proposer llm

■ fix_signatures_llm.py —— LLM 签名修复（核心，修 too few/many arguments）
    python fix_signatures_llm.py <binary> [options]

  关键参数：
    -o/--output-dir     重新反编译输出目录（覆盖原 decomp 目录）
    --functions NAME...  只处理指定函数名
    --prescreen          编译预筛：先 make -k 收集 too few/many 报错函数，只修它们
    --build-dir          --prescreen 时的 build 目录
    --max-functions N    最多处理 N 个函数
    --model              快模型（默认 deepseek-chat）
    --slow-model         慢模型兜底（如 deepseek-v4-pro），对快模型失败的函数重试

  推荐流程：
    python decompile_binary.py busybox -o out                     # ① 反编译
    python decompile_helper.py all busybox out/busybox_decomp \
        -o build --map busybox.map                               # ② 生成工程
    python fix_signatures_llm.py busybox --prescreen \
        --build-dir build -o out/busybox_decomp                  # ③ 预筛+修签名

■ fix_types_llm.py —— LLM 类型/结构体错误修复（修 array type / long 当指针等）
    python fix_types_llm.py <binary> <decomp_dir> --build-dir <build_dir> [options]

  关键参数：
    --build-dir          （必需）build 目录
    --max-functions N    最多处理 N 个函数
    --model / --slow-model  同 fix_signatures_llm

  示例：
    python fix_types_llm.py busybox out/busybox_decomp --build-dir build --max-functions 50

■ fix_signatures.py —— 签名修复基础版（手工 sigs.json）
    python fix_signatures.py <binary> --signatures sigs.json [-o out_dir] [--dump NAME]

  sigs.json 格式：
    [{"name": "apply_op", "signature": "int apply_op(int op, int a, int b)"}]

=====================================================================
四、完整端到端流程（推荐顺序）
=====================================================================

  # 1. 反编译（含 libc 类型/签名自动导入）
  python decompile_binary.py <binary> -o <work>

  # 2. 生成可编译工程（含 libc 过滤）
  python decompile_helper.py all <binary> <work>/<stem>_decomp \
      -o <work>/<stem>_build --map <binary>.map

  # 3. LLM 签名修复（预筛只修报错的，省成本）
  python fix_signatures_llm.py <binary> --prescreen \
      --build-dir <work>/<stem>_build -o <work>/<stem>_decomp

  # 4. （可选）LLM 类型错误修复
  python fix_types_llm.py <binary> <work>/<stem>_decomp \
      --build-dir <work>/<stem>_build

  # 5. 重新生成工程并编译
  python decompile_helper.py all <binary> <work>/<stem>_decomp \
      -o <work>/<stem>_build --map <binary>.map
  # （或直接 orchestrator 闭环）
  python orchestrator.py <binary> <work>/<stem>_decomp \
      -o <work>/<stem>_build --map <binary>.map --proposer llm

=====================================================================
五、GUI（desktop）
=====================================================================

  双击 启动反编译器.bat（或 python decompile_gui.py）

  功能：拖入二进制/目录 → 反编译 → [签名修复]（可设上限）→ [生成工程] → [静态修复]
  四界块可拉伸/隐藏；暗/亮主题；文件树过滤 .o；目录扫描排除 .o/.obj。
  LLM 相关操作需设置 LLM_API_KEY 环境变量。

=====================================================================
六、单元测试
=====================================================================

  python -m pytest test_core.py -v      # 31 个纯函数用例（无需 Ghidra，快）

=====================================================================
七、注意事项
=====================================================================

  - LLM 功能全部依赖 LLM_API_KEY 环境变量；fallback 规则库离线可用。
  - 静态链接二进制务必配 --map 过滤 libc，否则符号冲突。
  - 大文件先设 --max-functions 小值试跑，确认效果再全量。
  - 类型修复（fix_types）对「简单结构体」有效，对「深度类型推断」仍有边界。
