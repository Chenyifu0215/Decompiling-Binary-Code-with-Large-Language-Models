五、关键技术结论
--------------------------------------------------------------------------------
  1.【硬边界】整二进制「完整重编译通过」在无源码下 ~0%（业界共识）。
    int vs 指针 vs 结构体的类型信息在机器码里物理丢失。
  2.【全局变量类型是最大源头】globals.h 里按数据段大小猜的类型
    （size==8 -> long、size>8 -> 数组）导致 array type / unary / binary
    大量错误；改为按代码真实用法推断后消除约 1000 条。
  3.【用法推断优于大小猜测】按 *var（解引用）/ var & mask（位运算）/
    &var（取地址）推断类型，完全通用（不依赖名字）。
  4.【符号表规范化】Ghidra 把符号名里非标识符字符换成 "_"
    （ELF 的 dot.0 -> Ghidra 标识符 dot_0），可反查恢复声明。
  5.【stripped 降级】符号表反查 / 名字语义表依赖符号名，stripped 二进制
    失效；但用法推断 / slice / 数组赋值等不依赖名字的优化仍有效。
  6.【LLM 梯度】deepseek-chat 签名推断 ~0.5s/函数；签名迭代非单调，
    多轮可能负收益（需验证回退机制）。
  7.【静态 vs 动态链接】静态链接把 libc 内联成内部函数（名字带 glibc
    前缀），需别名去前缀匹配签名；动态链接有导入表可直接注入。

六、已知边界 / 未完成
--------------------------------------------------------------------------------
  - 跳转表（UNRECOVERED_JUMPTABLE）：Ghidra 输出 switchD_x::switchdataD_y
    （C++ 风格 ::），C 编译报 expected ';' before '::'。
  - stripped 二进制：符号名缺失，依赖名字的优化退化。
  - 结构体字段语义名、int 有符号性：机器码物理丢失。
  - 剩余 too few/many（483）：变参/复杂签名，LLM 推断已达天花板。
  - 功能正确性（运行时行为）未系统验证，仅做了函数级 demo。
